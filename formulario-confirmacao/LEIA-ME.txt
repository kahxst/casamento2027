FORMULÁRIO DE CONFIRMAÇÃO DE PRESENÇA — KAMILA & EWERTON

ARMAZENAMENTO
As confirmações são enviadas diretamente do navegador para a tabela
public.confirmacoes no projeto Supabase configurado em formulario-confirmacao/script.js.
O site permanece estático e pode ser hospedado no GitHub Pages. Não utiliza
Google Apps Script, PHP ou servidor próprio.

CAMPOS GRAVADOS
- created_at: data e hora automática do Supabase
- nome: nome completo informado pelo convidado
- comparecera: Sim ou Não

CONFIGURAÇÃO JÁ APLICADA
- Project URL e Publishable key configurados no script.js.
- A chave publishable pode ser pública no navegador. Nunca coloque uma chave
  secret ou service_role neste arquivo.
- A tabela public.confirmacoes deve ter RLS ativado e uma política INSERT para
  anon que valide nome e comparecera. Não crie política SELECT para anon.

SQL DE REFERÊNCIA (já executado no projeto)
  alter table public.confirmacoes enable row level security;
  grant insert on public.confirmacoes to anon;
  create policy "Permitir envio de confirmacoes"
  on public.confirmacoes for insert to anon
  with check (char_length(trim(nome)) >= 3 and comparecera in ('Sim', 'Não'));

PUBLICAÇÃO E TESTE
1. Publique a pasta casamento2027 no GitHub Pages, mantendo as subpastas.
2. Abra formulario-confirmacao/index.html pelo endereço publicado.
3. Envie uma confirmação de teste.
4. No Supabase, abra Table Editor > confirmacoes e verifique o novo registro.

SEGURANÇA
A chave publishable não é uma senha e foi feita para estar no front-end. A
proteção dos dados depende das políticas RLS. A política criada permite INSERT,
mas não permite que visitantes leiam os registros. Para consultar respostas,
use o painel autenticado do Supabase.
